# Authentication

## Files

| File | Location | Owner | Mode |
|---|---|---|---|
| `client_secret.json` | `$XDG_CONFIG_HOME/gdcli/` (default `~/.config/gdcli/`) | user (downloaded from Google Cloud, edited by the user) | 0600, directory 0700 when created by gdcli |
| `token.json` | `$XDG_DATA_HOME/gdcli/` (default `~/.local/share/gdcli/`) | program (yup-oauth2 token storage) | 0600 (set by yup-oauth2), directory 0700 |

Relative `XDG_*` values are ignored per the XDG specification (handled by the `xdg` crate). Setup and login create missing directories.

## Scopes

One token covers all commands; `login` requests all three scopes at once.

| Scope | Used by | Why this one |
|---|---|---|
| `https://www.googleapis.com/auth/calendar.events.readonly` | `calendar *`, `meet list` (upcoming) | narrowest read-only scope that allows `events.list` and `events.get` |
| `https://www.googleapis.com/auth/meetings.space.readonly` | `meet *` | allows `spaces.get`, `conferenceRecords.get/list`, participants, recordings, transcripts (read only); `meetings.space.created` would only see spaces created by this app |
| `https://www.googleapis.com/auth/drive.readonly` | `docs get` | `files.export` accepts `drive`, `drive.readonly` and `drive.file`; `drive.file` only covers files the app created or opened, so `drive.readonly` is the narrowest that works for arbitrary documents. `drive.meet.readonly` (the generated crate's default for export) only covers files generated by Meet and is not requested |

yup-oauth2 stores tokens per requested scope set and treats a token for a superset as valid for a subset. The generated hubs request their own default scopes, which differ per method, so `Token` (the `GetToken` implementation in `src/auth/token.rs`) ignores the requested scopes and always asks the authenticator for `SCOPES`. The token file therefore contains exactly one entry.

## Flows

- `gdcli login`: creates the data directory (0700) and deletes any stored token (so the flow always runs), builds the authenticator with `InstalledFlowReturnMethod::HTTPRedirect` and `force_account_selection(true)` (a local loopback server on a random port; the default flow delegate prints the authorization URL to stdout), waits for the redirect, exchanges the code, requests a token for `SCOPES` and prints the token path. The browser must run on the machine where gdcli runs (or the loopback port must be forwarded). No browser-opening dependency is used.
- `gdcli setup`: prints `docs/setup.md` (embedded at compile time, so the text exists once in the repository), prints the exact destination path, asks on stdin for the path of the downloaded JSON, then validates and installs it (`src/auth/secret.rs`) and runs the login flow. An empty answer means the file is already at the destination; it is then only validated. Validation requires the `installed` section, i.e. an OAuth client of type "Desktop app"; `web` clients are rejected.
- Every other command builds the authenticator with `InstalledFlowReturnMethod::Interactive` and a flow delegate (`NotLoggedIn`) whose `present_user_url` returns an error. yup-oauth2 only calls the delegate when it has no usable token (no token file, or refresh failed), so these commands never start a browser flow, never open a listening socket and fail immediately with `no valid token (missing, expired or revoked): run gdcli login`. A refresh failure caused by a network outage produces the same message. Valid and refreshable tokens work transparently; refreshed tokens are written back to `token.json`.
- Missing client secret: `cannot read client secret <path>: run gdcli setup`.

## HTTP stack for OAuth

yup-oauth2 is given a client built by gdcli (`CustomHyperClientBuilder`) with the same rustls connector as the API calls (ring crypto provider, bundled webpki root certificates). Its default client would scan the system certificate store.

## Refresh tokens

- The authorization URL carries `access_type=offline`. Google only returns a refresh token on the first consent of a user for a client; a repeated authorization without `prompt=consent` returns an access token only, which would leave gdcli unable to refresh after one hour. `force_account_selection(true)` makes yup-oauth2 add `prompt=select_account+consent` (yup-oauth2 `installed.rs`), so every `gdcli login` yields a refresh token. Non-login commands never build a flow URL, so they do not set it. A test starts the real binary and checks the printed URL.
- An OAuth consent screen in publishing status "Testing" issues refresh tokens that expire after 7 days. Publish the app ("In production"; unverified is fine for personal use, Google shows an unverified-app warning during login) or run `gdcli login` again. This is also written in `docs/setup.md`.
- Non-login commands create no directories: `$XDG_DATA_HOME/gdcli` is created by `login` only.
