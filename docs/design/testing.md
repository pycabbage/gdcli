# Testing

`cargo test` needs no credentials and no network access. Everything under `tests/` uses the library API or the built binary. 119 tests.

| File | Covers |
|---|---|
| `tests/units.rs` | document id and URL extraction; padded top-level values are trimmed; an unexpected nested object is rendered as a quoted JSON string and never dropped; `compact`, the generic text rendering of a record (one line per scalar and per array element, nested arrays, CRLF normalisation, `none` for an empty array) and its JSON rendering; text and JSON carry the same information line by line (an independent oracle in `tests/common` rebuilds the expected `key: value` and `name=value` lines from the record; three `should_panic` tests prove it notices a dropped nested `false`, a dropped field and values moved to another line); `table` in text and JSON (empty result `[]`); event time rendering; Meet link detection; path joining and XDG resolution with fake environments (relative values, passwd home, missing home); `is_broken_pipe`; `deadline_for`; the product description equal to the first README line and to the `--help` text |
| `tests/cli.rs` | clap `debug_assert`, parsing of every command, `--json` accepted exactly on `calendar list/get`, `meet list/get` and `docs metadata` and rejected on `docs get`, `setup`, `login`, `--past` / `--upcoming` / `--future` (defaults, range 0 to 1000, out-of-range and non-numeric values rejected), `docs get --tab` (blank values rejected with exit 2), rejection of unspecified flags, missing arguments, empty ids, event ids that could change the request path, document ids that cannot be ids, `--help`/`--version` |
| `tests/calendar_list.rs` | past/upcoming selection against a fake Calendar server (a closure that filters and pages a dataset by `timeMin`, `timeMax`, `maxResults`, `pageToken`): single window, window widening (exact `timeMin` of each request), fewer than 5 events in all windows, 300 events over two pages with the 5 newest kept, cancelled events paged over, ongoing events only in upcoming, ended all-day events dropped from upcoming, sanitised summaries; header line (exact names, `id` first, same column count as every row, header alone for an empty calendar, nothing printed on API failure); the exact `eventTypes` values on every request; the upcoming page size (calendar: N capped at 250; meet: N between 25 and 250); exact `fields`, `maxResults`, `orderBy`, `singleEvents`; counts honoured for N = 1, 3, 8, 12 on both sides with the exact `maxResults`, `0` skips a side with no request for it, larger past counts widen the windows and keep the newest N, `--json` rows equal the text rows, `[]` for an empty result |
| `tests/calendar_get.rs` | the curated record of an event: exact text, exact JSON bytes (ordered keys, UTC times, snake_case names, attendees with `optional` only when true, entry points, CRLF description), text and JSON line by line (the oracle in `tests/common`), the exact `fields` mask, a non-Meet conference keeps its `conference_id`, 404 |
| `tests/meet.rs` | `meet list`: only Meet events (non-Meet, other conference types, cancelled excluded), event id first for past and upcoming rows, the predicate applied before the past ring buffer, nested past windows, upcoming paging until 5 matches, ongoing/ended dedupe, header alone for no meetings, nothing printed on API failure, no Meet API request; `meet get`: exact requests (events.get fields, spaces.get fields, `conferenceRecords.list` with the exact filter string, `pageSize`, participants/recordings/transcripts masks and page sizes), multiple records oldest first, `conference: none`, all-day event (filter by code only), event without Meet conference, unknown event, 403/404 tolerance line, 403 on the record list or on one artifact call (the rest is printed), other Meet errors fail without output; every mock requires `Authorization: Bearer <token>`; `meet get` text and JSON equivalence (nested `conferences` with participants, recordings, transcripts), `conference: none`, counts and `--json` for `meet list` |
| `tests/docs.rs` | Markdown export streaming of a 1 MB body for a bare id and several URL shapes, export errors; the tab tree flattened (parents, levels, defaults for omitted zero values) with the exact Docs API `fields` mask; tab resolution (id, `t.`-prefixed id, title, case-insensitive title, ambiguity and not-found messages with candidates); `docs get --tab`: Authorization on the export request, the 307 target fetched without it (answering the real `text/x-markdown; charset=utf-8` and `text/markdown`; `text/html`, `text/plain`, `application/json` and look-alikes rejected; matching is case-insensitive: `Text/X-Markdown; Charset=UTF-8` and `TEXT/MARKDOWN` accepted, `Text/HTML` rejected), wrong redirect host rejected, a second redirect is an error and is not followed, the redirect allowlist `google::googleusercontent` tested with look-alike hosts (`evilgoogleusercontent.com`, `googleusercontent.com.evil.com`, bare domain, http, trailing dot, userinfo tricks, protocol-relative and relative locations), the `t.` prefix guard, a throttled 429 HTML answer, unknown or ambiguous tab never reaches the export; `docs metadata`: exact Drive request (`supportsAllDrives`, `fields`), text and JSON, not-a-doc error, tolerated Docs API failure (`tabs_unavailable`), Drive failure |
| `tests/errors.rs` | non-JSON error bodies print only `google api error <status> <reason>`; JSON bodies without `error.message`, empty bodies and non-JSON success bodies map to fixed short messages and never echo the body; Meet path segments are percent-encoded one per id and `.`/`..` are rejected; `with_deadline` fails a never-answering mock with `timed out after 1s`, passes results through, and `None` means no deadline; the production limits (10 s, 120 s); the production connector and client refuse plain `http://` (zero requests reach a local server); Google messages are cut at 300 characters |
| `tests/secret.rs` | client secret validation (installed vs web vs garbage), copy with mode 0600, directory creation, tightening of an existing 0666 file, rejection without touching the destination, typed path cleanup (quotes, `~/`), `setup` prompt behaviour for bad paths and empty answers (every `setup` call is wrapped in a 5 s timeout so a validation regression fails instead of reaching the login flow) |
| `tests/auth.rs` | `SCOPES` equal to the scopes listed in `docs/setup.md`; the real `gdcli login` binary prints an authorization URL with `access_type=offline`, `prompt=select_account+consent`, the loopback redirect, the client id and all scopes, and has deleted the stored token by then; the URL is read on a reader thread with a 20 s timeout and the child is killed by a drop guard |
| `tests/binary.rs` | the real binary with `XDG_CONFIG_HOME`, `XDG_DATA_HOME` and `HOME` set per process (no mutation of the test process environment): missing client secret, XDG and `$HOME` fallback paths, relative XDG values ignored, missing token fails fast with `gdcli login` for every API command, corrupt token file, usage error exit code 2, help and version, lowercase first letter of error output; every child process is polled against a 30 s deadline and killed, so a regression that makes a command wait for a login fails instead of hanging; closed stdout exits 0 with empty stderr (read end of the pipe closed before spawn); empty ids exit with status 2 |
| `tests/common/mod.rs` | shared `wiremock` harness: `Google` wired to the mock with a plain-HTTP connector and a `yup_oauth2::AccessTokenAuthenticator`, event builders and the fake Calendar server |

Testability design: command functions take the `Google` facade, the current time and the output writer as parameters; `Google::new` takes the two root URLs; the token source is yup-oauth2's `AccessTokenAuthenticator` in tests; `Paths::new` takes explicit directories.

Not covered by automated tests (needs real credentials or Google's servers): the interactive OAuth login against Google, token refresh, real API payloads, the HTTP/2-only client and the 10 s connect timeout, and the line in `run()` that applies `deadline_for` (the pure function and `with_deadline` are tested; wiring them needs a command that hangs). During development the login URL and loopback server were exercised manually with a fake client id, and API calls with a bogus token (Google answered 401, proving TLS with the bundled roots, HTTP/2 and request routing for Calendar, Drive and Meet; `strace` showed one connection per command).

The local toolchain must be the latest stable, because CI uses `@stable` and lints change between releases (`rustup update stable && rustup component add clippy rustfmt`; see `lints.md`). The local quality gates are `cargo fmt --check`, `cargo clippy --all-targets --locked -- -D warnings`, `cargo test` and `cargo build --release --locked`. CI (`.github/workflows/ci.yml`) runs fmt, clippy, build and test.
