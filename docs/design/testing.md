# Testing

`cargo test` needs no credentials and no network access. Everything under `tests/` uses the library API or the built binary. 79 tests.

| File | Covers |
|---|---|
| `tests/units.rs` | document id and URL extraction, `row` / `field` / `flatten` output helpers, event time rendering (UTC seconds, dates), Meet link detection, path joining, `is_broken_pipe` (only a top-level `BrokenPipe`, not one inside a network error), `deadline_for` (none for `setup` and `login`, 120 s for API commands), the product description equal to the first README line and to the `--help` text |
| `tests/cli.rs` | clap `debug_assert`, parsing of every command in the spec, rejection of unspecified flags (`docs get --json`, `--limit`, ...), missing arguments, empty ids, event ids that could change the request path (`.`, `..`, `%2e`, `%2e%2e`, `/ ? # %`), `--help`/`--version` |
| `tests/calendar_list.rs` | past/upcoming selection against a fake Calendar server (a closure that filters and pages a dataset by `timeMin`, `timeMax`, `maxResults`, `pageToken`): single window, window widening (exact `timeMin` of each request), fewer than 5 events in all windows, 300 events over two pages with the 5 newest kept, cancelled events paged over, ongoing events only in upcoming, ended all-day events dropped from upcoming, sanitised summaries; header line (exact names, `id` first, same column count as every row, header alone for an empty calendar, nothing printed on API failure); the exact `eventTypes` values on every request; exact `fields`, `maxResults`, `orderBy`, `singleEvents` |
| `tests/calendar_get.rs` | the flattened `calendar get` output (dotted keys, indexed arrays, multi-line description, raw timestamps), the exact `fields` mask, 404 |
| `tests/meet.rs` | `meet list`: only Meet events (non-Meet, other conference types, cancelled excluded), event id first for past and upcoming rows, the predicate applied before the past ring buffer, nested past windows, upcoming paging until 5 matches, ongoing/ended dedupe, header alone for no meetings, nothing printed on API failure, no Meet API request; `meet get`: exact requests (events.get fields, spaces.get fields, `conferenceRecords.list` with the exact filter string, `pageSize`, participants/recordings/transcripts masks and page sizes), multiple records oldest first, `conference: none`, all-day event (filter by code only), event without Meet conference, unknown event, 403/404 tolerance line, 403 on the record list or on one artifact call (the rest is printed), other Meet errors fail without output; every mock requires `Authorization: Bearer <token>` |
| `tests/docs.rs` | Markdown export streaming of a 1 MB body for a bare id and several URL shapes, export errors |
| `tests/errors.rs` | non-JSON error bodies print only `google api error <status> <reason>`; JSON bodies without `error.message`, empty bodies and non-JSON success bodies map to fixed short messages and never echo the body; Meet path segments are percent-encoded one per id and `.`/`..` are rejected; `with_deadline` fails a never-answering mock with `timed out after 1s`, passes results through, and `None` means no deadline; the production limits (10 s, 120 s) |
| `tests/secret.rs` | client secret validation (installed vs web vs garbage), copy with mode 0600, directory creation, tightening of an existing 0666 file, rejection without touching the destination, typed path cleanup (quotes, `~/`), `setup` prompt behaviour for bad paths and empty answers (every `setup` call is wrapped in a 5 s timeout so a validation regression fails instead of reaching the login flow) |
| `tests/auth.rs` | `SCOPES` equal to the scopes listed in `docs/setup.md`; the real `gdcli login` binary prints an authorization URL with `access_type=offline`, `prompt=select_account+consent`, the loopback redirect, the client id and all scopes, and has deleted the stored token by then; the URL is read on a reader thread with a 20 s timeout and the child is killed by a drop guard |
| `tests/binary.rs` | the real binary with `XDG_CONFIG_HOME`, `XDG_DATA_HOME` and `HOME` set per process (no mutation of the test process environment): missing client secret, XDG and `$HOME` fallback paths, relative XDG values ignored, missing token fails fast with `gdcli login` for every API command, corrupt token file, usage error exit code 2, help and version, lowercase first letter of error output; every child process is polled against a 30 s deadline and killed, so a regression that makes a command wait for a login fails instead of hanging; closed stdout exits 0 with empty stderr (read end of the pipe closed before spawn); empty ids exit with status 2 |
| `tests/common/mod.rs` | shared `wiremock` harness: `Google` wired to the mock with a plain-HTTP connector and a `yup_oauth2::AccessTokenAuthenticator`, event builders and the fake Calendar server |

Testability design: command functions take the `Google` facade, the current time and the output writer as parameters; `Google::new` takes the two root URLs; the token source is yup-oauth2's `AccessTokenAuthenticator` in tests; `Paths::new` takes explicit directories.

Not covered by automated tests (needs real credentials or Google's servers): the interactive OAuth login against Google, token refresh, real API payloads, the HTTP/2-only client and the 10 s connect timeout, and the line in `run()` that applies `deadline_for` (the pure function and `with_deadline` are tested; wiring them needs a command that hangs). During development the login URL and loopback server were exercised manually with a fake client id, and API calls with a bogus token (Google answered 401, proving TLS with the bundled roots, HTTP/2 and request routing for Calendar, Drive and Meet; `strace` showed one connection per command).

The local quality gates are `cargo fmt --check`, `cargo clippy --all-targets --locked -- -D warnings`, `cargo test` and `cargo build --release --locked`. CI (`.github/workflows/ci.yml`) runs fmt, clippy, build and test.
